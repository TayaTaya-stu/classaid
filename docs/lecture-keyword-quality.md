# 講義キーワードの選別（v15）

## 目的
音声認識の原文を保存したまま、誤認識らしい教科書の課番号・ページ番号や無関係な発言を返信の根拠から外す。資料はPDF/公開Notionどちらも同じ照合先で、資料なしでも既知のIT用語と説明のある発話は利用する。

## 実装
- 音声保存時、資料に実際に記載された語句と音声の一致を優先する。資料外では、保守的なIT用語リストと説明・利用・仕組み等の関係を示す表現の両方を含む文を候補にする。
- ページ/課/章/節の番号を除き、挨拶・提出等の一般的な教室語や「日本語」「玄関」「鍵」単独をキーワードにしない。資料にあるだけでは扱った内容にしない。
- 本番ジョブが投稿時刻で取得した音声アーカイブを、返信前に再選別する。過去に保存済みの怪しいkeywords/keyword_contextsをそのまま再利用せず、原文から判定し直す。
- 不採用の文を直近発話・時系列参照根拠から外す。採用した文の周辺説明は残す。原文DBは書き換えない。
- 資料一致用語を優先した採用リストをプロンプトに明示。少数の用語を投稿に合わせて扱い、関係のない別分野の概念を増やさないよう指示する。
- 「108ページ」「第2課」等を授業接続返信が出した場合、人間投稿自身が番号に言及していなければ予備返信へ切り替える。
- プロンプト版: reaction-v15-qualified-lecture-keywords。予備返信版: reaction-fallback-v15。
- contextMetadata.keywordQualityに選別版・採用語・資料一致語・採用/除外レコードIDを記録する。archiveRecordIdsは従来どおり、取得した原文記録全体のIDなので採用IDとは別。
- 追加のLLM呼び出しなし。録音・音声認識モデル・音声ファイル非保存・全文保存・120分終了・生成5秒期限は変更しない。SQL追加不要。

## 精度上の限界
これはルールによる保守的な選別で、ASRの正誤を音声から判定する機能ではない。資料と同じ語を誤認識した場合もあり、一致は正しさの証明ではない。IT用語リストにない正しい専門用語が、資料なしでは除外されることもある。意味の自然さを完全に判定するものではなく、短い句や表記揺れを取り逃すことがある。番号の出力制限は実際に話されたページ番号も抑える。授業内容の接続で不要な番号を出さない方針。

## 検証
- tests/lecture-keyword-quality.mjsは実際のcontext/generatorを対象に、108ページの第2課、資料内にもある日本語という一般語、玄関の鍵、不明語を除外することを確認。
- 公開鍵暗号の説明を資料と照合し、資料なしのデータベースの説明を採用。将来の音声・未習資料語を使わないことを確認。
- 原文保存時にp_textが変わらず、keywordsだけ選別されることを確認。生成AIへの入力に除外した文が残らないこと、診断ID、番号を含む出力の予備返信への切替を確認（認識結果・API応答はスタブ）。
- 既存の音声API→context→ローカルSQLアーカイブの統合テストも実行。実マイク/Googleの認識精度/150人負荷はこの検証では測定しない。
