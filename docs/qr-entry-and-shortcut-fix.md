# QR・固定入口・ショートカットの修正

対象: supportalk-sharedwall-audio-fix.zip適用済みコード（SQLは019適用済み）。旧020パッチは不要。

## 変更
- 学生向けの固定入口 `/join` を追加。管理者が「今回使用する」と指定した1件だけに303リダイレクトし、キャッシュしない。
- 未指定・複数指定・終了・120分超過では過去の授業を推測で選ばず案内を表示。
- 古い授業のentrySlugからの入室を拒否。学生のルームアクセスも現在の指定回でなければ拒否し、過去の部屋への新しい投稿・いいねを防ぐ。
- アプリが選択した回と指定回が違えばQR表示を拒否する。
- `STUDENT_BASE_URL`でPC内のAPI接続先とスマホ向け接続先を分ける。localhostをスマホ用QRに使わない。
- QR上部にURL表示、不要なLINEの注意文を削除。高い最前面レベルを指定し、フォーカスを奪わず重なり順を復帰。
- 旧アプリとの競合を避け、SupporTalk専用の設定保存先とアプリ識別を使用。既存設定は初回のみコピーし、旧版の設定は変更しない。
- 新ショートカットはCtrl+Alt+Shift+S。登録不可時はCtrl+Alt+Shift+Tを試し、実際に登録できたキーをアプリ下部へ表示。両方失敗した場合も表示する。旧Ctrl+Shift+Oは登録しない。

## 自宅での接続設定
`.env.local`に次を設定（他の項目は維持）:

STUDENT_BASE_URL=http://192.168.11.12:3000

これは今回確認されたWi-FiのPCアドレスを使う自宅テスト用設定。Wi-FiやPCのアドレスが変われば更新が必要。本番で1枚のQR画像を継続利用するには、最終的に固定の公開HTTPS URLを設定する。

## 適用後
1. 実行中のSupporTalkアプリだけを終了。旧版や開発サーバーを一括終了しない。
2. Apply-Fix.ps1でコードを適用。元コード不一致なら止め、強制適用しない。
3. STUDENT_BASE_URLを設定し、開発サーバーを再起動（既存サーバーをCtrl+C→npm run dev）。ポート3000を確認。
4. npm run overlayでアプリを再起動。
5. 管理者画面で試運転対象を「今回使用する」に指定。アプリでも同じ回を選択。
6. QR上のURLが http://192.168.11.12:3000/join であることを確認。
7. スマホを同じWi-Fiへ接続してQRを読み、入室画面が開くか確認。
8. 他画面をクリックしてもQRが残るか、操作画面を閉じた後でアプリ下部表示のショートカットにより復帰するか実機確認。

PC自身から192.168.11.12へHTTP200が返ることだけではスマホからの接続を保証しない。失敗時はWindowsファイアウォール・ネットワーク分離等を個別に調べる。ファイアウォールの一括無効化はしない。
新しいSQL・依存パッケージは不要。Windowsの実フォーカス・全画面描画・スマホ通信は実機確認が必要。
