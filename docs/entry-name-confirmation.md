# 入室前の名前確認

## 表示

- 通常の入室では、ブラウザの保存情報の有無によらず、名前入力・同意選択のあとに確認画面を出す。
- 「前回と同じ名前ですか？」、入力した名前を大きく表示、初参加向け案内、記録の分断や他の学生の名前との重複について小さな補足を表示する。
- 確認画面の「この名前で入室する」を押すまでは、入室POSTを送らない。研究同意は「同意する」「同意しない」のどちらでも入室可能。
- 「名前を入力し直す」は名前と同意選択を保って入力画面へ戻る。
- 「前に使った名前がわからない」は入力画面と確認画面の両方で、太い黄系の枠と背景・大きめのボタンにする。
- 名前不明の案内を開く・戻るだけでは認証・参加者を変更しない。「新しい名前で参加する」を明示的に押したときだけ既存の直列化した認証切り替えを行う。
- 切り替えが成功すると入力画面で新しい名前を入力する。その後の確認見出しは「新しく使う名前を確認してください」とし、前回と同じ名前を要求しない。
- 既存名の自己申告引き継ぎ警告・他人の記録との混同を防ぐサーバー判定は残す。ブラウザをまたいだ本人認証機能が新しく付くものではない。
- 入室の連打は未完了の1件に制限。通信・本人確認エラー時も名前不明の案内へ進める。

## 検証

- `node tests/entry-name-confirmation.mjs`: 実際のページのイベントハンドラーを実行。新規／既存、同意有／無、未確認時POSTなし、修正後の名前と同意保持、連打防止、APIエラー、既存名引き継ぎを確認。
- `node tests/forgot-name-visible.mjs`: 入力画面と確認画面双方からの名前不明案内、取り消しで認証維持、新規登録時の直列実行、サインアウト失敗時中断を確認。
- `node tests/name-recovery-entry.mjs` / `node tests/entry-blank-name.mjs`: 既存の登録ログと名前空欄の動作を確認。
- TypeScript型チェックと変更ファイルのESLintを実施。
- 実スマホでの表示・操作確認はWeb反映後に行う。
