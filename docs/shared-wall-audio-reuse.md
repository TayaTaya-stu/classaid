# Shared Wall音声処理の再利用

対象: supportalk-review-019.zip。前に渡したsupportalk-019-fix-020.zipは適用しない。この修正に020のSQLは含めない。

## 実物で確認した旧版

shared-wall-audio-reference.zip内のAdminSessionControl.tsxは、getUserMedia（echoCancellation/noiseSuppression）とMediaRecorderを使う。15秒ごとに録音器を作り直すため、各WebM/Opusファイルが単独で読み取れる。直近95秒だけメモリに保持し、手動生成時に音声Blobをmultipart送信する。
旧generate/route.tsは、受信音声をサーバーでBase64化し、Geminiへ同じ文字起こし指示で送る。experiment-config.tsのモデル順は3.1-flash-lite → 3.5-flash-lite → 3.8-flash。019側の同ファイルも一致しており、変更していない。

## 再利用と必要な変更

- 録音: 上記の取得オプション・MIME候補・独立15秒ファイル方式をElectronの既存操作画面へ移した。Chromeの別プロセス、Web Speech API、使い捨てチケットは使用しない。
- 自動化: 手動候補生成ボタンからの送信を、録音完了時のバックグラウンド送信に変更。学生投稿の返信処理は音声の完了を待たない。
- 保持・負荷: 未送信音声を最大95秒・7区間・12MBまで保持。同時送信は1件、保存済み区間を繰り返し送らない。通常は新しい15秒区間を文字起こしし、通信遅延時だけ未送信区間をまとめる。これは自動運転での重複処理を減らすための変更。
- 文字起こし: 既存のモデル順と文字起こしプロンプトを維持。要約JSONを求める別方式にはしない。実際に成功したモデルを記録。
- 文脈: 既存appendSpeechTextへ結果を渡す。過去の学術語句・進行記録を使う既存AI返信の経路は維持。
- 停止: マイクのトラック停止、録音・送信の中止、バッファ破棄。投影停止／再試行は音声を止めず、AI停止・授業終了・120分経過は音声を止める。
- 取り消し: Chromeワーカーの2つの認証APIは410にし、補助画面を案内だけに変更。新しい020認証テーブルは不要。
- アプリのつなぎ修正: 3001で検出した接続先の維持、初回接続設定、QRの授業回・投影先反映、開始時刻のローカル捏造を撤去。既存019の授業指定はそのまま利用。

## 費用と外部送信

旧版と同様にGoogleのGemini APIへ音声を送信する。無料か有料かは既存APIプロジェクトの設定・上限に依存し、無料と断定しない。
手動実行から自動実行になるため呼出し頻度は増える（15秒ごとなら120分で最大約480回、失敗時フォールバックは別途）。モデルを変更したための増加ではない。新しい長時間実API試験は行っていない。
音声ファイルは自システムではメモリ内の一時処理のみ。Google側の取り扱い・保存期間を「ゼロ」とは断定しない。

- 実際のaudio-reference.jsに仮想マイク・Recorderを渡し、独立ファイル、95秒破棄、同時1送信、保存済み区間の除去、停止後に遅れて届く許可・応答の処理を確認。
- 実際のaudio-transcription.tsをスタブGoogle通信で動かし、旧モデル順、MIME、プロンプト、入力検証を確認。
- 実際のElectron main.cjsのIPC処理をVMで動かし、3001へのmultipart送信、認証ヘッダー、音声と投影の独立停止、Chrome子プロセス不要を確認。
- 型チェック、lint、本番ビルド、既存のDBフローテスト。
- 未確認: Windowsでの実マイク、実Google APIの認識品質・遅延・使用枠、大学プロジェクター、120分連続稼働、大人数投稿。
