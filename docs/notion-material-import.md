# Notion等の資料本文の貼り付け登録

URL自動取得は、教授PCからのHTTP 403が確認されたため停止した。管理画面のURL自動取得フォームを、本文の貼り付けフォームに置き換える。

## 授業前の準備
1. Notionで授業に使う本文をコピーする。
2. 管理画面で対象の授業回を選ぶ。
3. 「授業資料（本文を貼り付けて登録）」に本文を貼り付ける。
4. 資料名・Notion元URLは任意。元URLは出典として記録するだけで、通信には使わない。
5. 画面の本文・文字数を確認して「本文を登録」を押す。成功時は保存した文字数を表示する。

## 保存
- 本文20万文字以内。前後の空白と改行コードの正規化以外、本文をAIで書き換えない。順序を保って最大4000文字ずつの区間に分ける。
- 区間ごとに本文、資料名、sourceType=pasted_text、Notion元URL（入力された場合）、登録日時を保存する。Notionの実blockIdやPDFページ番号は捏造しない。page欄は互換性のための区間通番。
- 元URLはNotion共有URLを検証し、ページIDに正規化する。URLのクエリやフラグメントは保存しない。元URLがなくても本文を保存できる。
- 既存のlecture_contexts.pdf_topicsに本文・メタデータを保存する。sessions.pdf_file_urlはnotion:<URL>、URLなしではtext:manual。既存DB構造の互換名を維持している。
- PDFと貼り付け本文は同じ資料枠。どちらかの登録で現在の資料を置き換える。両方を同時に保持する機能ではない。
- 元のNotionを書き換えても自動反映はしない。変更した場合は開始前に再登録する。
- 貼り付けた範囲だけが対象。画像・動画・リンク先ページの文章は自動取得しない。

## 安全性
- 管理者認証が必須。入力検証エラー・保存失敗では以前の資料を維持する。
- 既存register_lecture_pdf RPCが、本文と登録元を同一トランザクションで更新し、授業開始前であることも再検証する。
- 画面取得後に授業が開始された競合でも、DB側の開始済み検査で更新を拒否する。
- 非公式Notion取得エンドポイントへの実行経路を削除。古い画面のimport_notion要求はHTTP 410で案内し、データを変えない。
- 外部HTTPアクセス、追加のAI呼び出し、追加SQLなし。資料なしの動作・音声優先・未習資料語の先取り防止・キーワード選別・録音方式は変更しない。

## 確認範囲
- tests/notion-material.mjs: 実際の本文処理、管理API、context保存処理を、全マイグレーション適用済みのローカルPGliteと接続して確認。
- 本文と元URL/資料名/日時の永続化、長文の無欠落分割、入力エラー・認証エラー時の未更新、旧URL取得停止、PDF登録経路の維持、開始直前の競合・開始後の変更拒否を確認。PDFパーサーとStorageはこのテストでは代替実装。
- 実際の管理画面コンポーネントのHTML出力をReactで確認。入力・クリックを含むWindowsブラウザでの実操作とリモートSupabase登録は、適用後に確認する。
